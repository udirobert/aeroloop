## The TrueForge challenge

"Build an agent that gets better every time it runs" (sponsor: TrueForge by
TrueFoundry, `npx @truefoundry/trueforge@latest`). An agent on TrueForge that
reviews its own runs, rewrites its own instructions/skills, and scores higher
next run. Auto-checked requirements:

- Public repo, **not a fork**, created on/after Sat 31 Oct (template-made OK)
- Repo layout: `agent/` (agent.json, instructions.md, skills), `evals/tasks/`
  (3+ tasks, holdouts allowed), `evals/score.*`, `runs/summary.csv`, README
  with a **"Run 1 vs run N"** section
- `summary.csv`: 2+ runs, same tasks + scorer, a later run > run 1
- A commit to `agent/` between run 1 and the later run, message ending
  `Agent-Session: <session_id>` — **the agent writes the change, not you**
- Every counted run is a **TrueForge session**
- Use 2+ of: skills, subagents, MCP tools, sandbox, schedules, human
  checkpoints, the SDK
- Plus: ≤2 min video, 3-line blurb, half-page TrueForge feedback note

## Track: Hard problems

TrueForge is a **Hard problems** challenge, which changes two things vs. the
Real users track:

- **Ship it = the public repo.** No deployment needed — the repo is the
  public link (§4: "anyone can open it, logged out (Hard problems: a public
  GitHub repo)").
- **Feedback = judge confirmation.** No Trick-or-Feedback note required; a
  judge confirms the technical goal: "the public repo with the agent running
  on TrueForge, and a later run that improved on run 1 by changing its own
  skills or instructions" (§5).

## Plan: retrofit this repo

Add the TrueForge harness alongside `backend/` — nothing existing changes:

- `agent/` — TrueForge agent definition: `agent.json`, `instructions.md`, and
  a `skills/pm25-strategy/SKILL.md` encoding the estimation strategy (the part
  the agent rewrites — replaces "propose params via HTTP" with "rewrite your
  own playbook")
- `evals/tasks/*.json` — fixed PM2.5 prediction tasks (features + known ground
  truth from `data/`; mark 1–2 `holdout: true`)
- `evals/score.*` — deterministic scorer: PM2.5 error vs ground truth → one
  number (port of `evaluation.py`'s MAE logic)
- `scripts/` — copy + adapt the starter's run-evals / improve / setup TS
  scripts (or drive TrueForge's HTTP API from Python — the SDK is TS, the API
  is plain HTTP on localhost:8790)
- `runs/` — generated by run-evals
- README: add a **Run 1 vs run N** section (exact heading — it's checked)

TrueForge accepts custom OpenAI-compatible providers including local Ollama
(`OUTBOUND_URL_ALLOWED_HOSTS='["127.0.0.1"]'`), so the Gemma → Ollama
open-weight stack carries over. Need 2+ of: skills, subagents, MCP, sandbox,
schedules, human checkpoints, SDK — skills + SDK + subagents is the easy set.
